# 摸鱼二号（FishTwo）— Edge 图片阅读插件 · 需求方案

> 版本：v0.1（需求设计阶段）  
> 状态：待用户审核  
> 说明：本文档仅描述需求与技术方案，不包含实现代码。

---

## 1. 项目概述

### 1.1 背景
Edge 浏览器默认无法直接打开一个本地文件夹，批量识别其中的图片并进行统一排版阅读。用户在查看相册、漫画、截图等成组图片时，往往需要逐个点击打开，体验割裂。

「摸鱼二号（FishTwo）」旨在解决这一痛点，提供简洁美观的批量图片阅读体验。

### 1.2 命名
- 中文名：**摸鱼二号**
- 英文名：**FishTwo**

### 1.3 目标
- 导入文件夹，识别图片并按名称排序
- 提供三种阅读模式（下拉滚动 / 单页翻页 / 双页翻页）
- 支持图片缩放与一键还原
- 界面简洁美观、交互方便，支持中英文切换
- 提供 popup 弹窗便于用户配置
- 左侧图片列表导航，点击图片名快速跳转
- 只做核心功能，不做冗余功能

## 2. 技术选型（基于 Context7 检索确认）

| 层面 | 选型 | 理由 |
|---|---|---|
| 扩展规范 | Manifest V3 | Edge 基于 Chromium，MV3 为现行标准 |
| 构建框架 | **WXT**（底层 Vite） | 检索确认 WXT 原生支持 Chrome / Firefox / **Edge** / Safari / Chromium，提供文件式入口、HMR、TypeScript、自动打包发布，为当前更现代方案 |
| 备选构建 | CRXJS（@crxjs/vite-plugin） | 同为 Vite 插件式，成熟稳定，作降级备选 |
| UI 框架 | React + TypeScript | 组件化开发、类型安全，符合项目偏好 |
| 文件夹读取 | File System Access API | `showDirectoryPicker` + 句柄持久化 |
| 数据存储 | chrome.storage + IndexedDB | 配置存 storage.sync；文件夹句柄、图片索引存本地 IndexedDB |
| 国际化 | chrome.i18n（_locales） | 官方机制，支持中英文 |

> 用户已确认技术栈：**React + TS + Vite / File System Access API / Ctrl+滚轮+双击还原 / 常见图片格式**。

## 3. 页面结构

| 页面 | 说明 |
|---|---|
| reader 阅读页 | 核心页面，以独立标签页打开；负责导入文件夹、图片展示、阅读模式、缩放；左侧含图片名称列表导航 |
| popup 弹窗 | 点击工具栏图标弹出；提供配置入口与「打开阅读器」按钮 |

**入口设计**：点击扩展图标弹出 popup；popup 内含配置项与打开阅读器的入口。文件夹导入与图片阅读均在 reader 全页进行（原因见第 9 节风险说明）。

## 4. 核心功能需求

### 4.1 导入文件夹
- 用户在 reader 页触发 `showDirectoryPicker` 选择文件夹。
- 仅遍历所选文件夹**顶层**，识别支持的图片格式（jpg / jpeg / png / webp / gif / bmp）。
- 若检测到子文件夹，提醒用户「只能导入单一文件夹」，并忽略子文件夹内容。
- 默认按文件名从小到大**自然排序**（数字感知，如 `2.png` 排在 `10.png` 之前）。
- 持久化文件夹句柄，实现「记住最近打开的文件夹」，二次打开无需重新选择（有权限时）。

### 4.2 状态栏
- **顶部功能栏**（居中）：导入文件夹、阅读模式切换、缩放控制、语言切换。
- **底部信息栏**（居中）：当前页码 / 总页数、当前文件名、缩放比例。
- **隐藏机制**：两栏均支持隐藏（工具栏按钮或快捷键切换），隐藏后悬浮吸边可随时唤回。

### 4.3 三种阅读模式
1. **下拉滚动**：图片纵向连续排列，鼠标滚轮滚动浏览。
2. **单页翻页**：一次展示一页，支持前后翻页（方向键 / 点击 / 滚轮）。
3. **双页翻页**：两页并排展示（漫画阅读式），翻页节奏为两页一组。

### 4.4 缩放与还原
- **缩放**：鼠标在图片上 `Ctrl + 滚轮` 缩放（与网页缩放习惯一致）。
- **还原**：双击图片或点击还原按钮，恢复 100% 原始尺寸。
- 底部信息栏实时显示当前缩放比例。

### 4.5 目录栏（图片列表导航）
- 阅读页左侧提供独立目录栏，以**列表形式**展示图片名称（不含文件夹名）。
- 目录栏不显示图片缩略图，仅展示图片名称文本。
- 点击图片名称，按当前阅读模式快速跳转：滚动模式滚动定位到对应图片；单页/双页翻页模式跳转至对应页码。
- 当前阅读位置在列表中实时高亮，列表与阅读进度双向同步。

## 5. 交互设计要点

- 图片居中展示，背景随主题（亮色 / 暗色）自适应。
- 阅读模式切换即时生效，不需刷新。
- 缩放以鼠标指向位置为中心，避免图片跳动。
- 空状态提示（未导入文件夹时引导操作）。
- 图片列表与阅读位置双向同步：当前图片在列表中高亮，点击列表项跳转对应页。
- 键盘快捷键：翻页、缩放、隐藏状态栏、切换模式。

## 6. popup 配置项

| 配置项 | 选项 | 默认 |
|---|---|---|
| 语言 | 中文 / English | 跟随浏览器语言 |
| 默认阅读模式 | 下拉滚动 / 单页翻页 / 双页翻页 | 下拉滚动 |
| 主题 | 亮色 / 暗色 | 亮色 |
| 默认缩放 | 100% 或记忆上次 | 100% |
| 最近文件夹 | 列表 + 打开 | — |

> 配置通过 chrome.storage.sync 同步，reader 页实时读取并应用。

---

## 7. 扩展权限（最小化）

- **不需要** host 权限、**不需要** content script（不注入网页内容）。
- File System Access API 为 Web 平台能力，无需额外 Chrome 权限。
- 仅需扩展本身最基本权限，遵循最小权限原则。

---

## 8. 性能设计

- **大文件夹懒加载**：目录异步遍历，按需读取图片，避免一次性加载全部文件。
- **虚拟滚动 / 分页**：下拉滚动模式下仅渲染可视区域附近的图片。
- **对象 URL 回收**：缩放或切换后及时 `revokeObjectURL`，释放内存。
- **图片列表虚拟滚动**：目录栏图片过多时仅渲染可视区域项，保持流畅。
- **异步解码**：使用 `createImageBitmap` 等异步解码，避免阻塞主线程。

---

## 9. 风险与边界

- **File System Access API 限制**：`showDirectoryPicker` 需在扩展页面（非 content script）且由用户手势触发；在 popup 尺寸受限的弹窗中不可靠，因此统一在 reader 全页处理文件导入。
- **超大原图内存**：超大尺寸图片需配合缩放策略与对象 URL 回收，避免内存溢出。
- **句柄权限过期**：浏览器可能回收文件夹权限，需提供「重新授权」引导。
- **图片格式差异**：动图（gif）在缩放/翻页下的行为需单独处理（如保留原始尺寸播放）。

---

## 10. 实施建议（阶段划分）

1. **阶段一**：WXT 项目脚手架 + 扩展基础结构（manifest、reader 页、popup）。
2. **阶段二**：文件夹导入 + 图片识别排序 + 句柄持久化。
3. **阶段三**：三种阅读模式 + 状态栏（含隐藏）。
4. **阶段四**：缩放与还原 + 比例显示。
5. **阶段五**：popup 配置 + 中英文国际化。
6. **阶段六**：性能优化（懒加载、虚拟滚动）+ 打磨与联调。
